### API deploy handshake (CRITICAL)
iisnode locks `dist` + the Prisma engine DLL while the pool runs. **User** stops the pool → then:
`npx prisma generate` (only if schema changed) → `npx tsc -p tsconfig.json --outDir dist` → **user** starts the pool.
- `npx prisma db push --skip-generate` is SAFE while the pool runs; `prisma generate` is NOT.
- New-Prisma-model code shows "property does not exist on PrismaService" typecheck errors until the handshake — expected, not a bug.
- **NEVER run root `npm run build` (turbo) while the pool runs** — nest's clean step guts `dist` and causes a delayed outage. Build workspaces individually.
- Seed is CLEAN-SLATE — never run against prod. Use `npm run ensure-roles` for additive role changes.
- **ALWAYS boot-test before handing the build back**: `PORT=3999 node dist/main.js` and look for "Nest application successfully started". `tsc` passing proves NOTHING about dependency injection — a controller injecting a service whose module wasn't imported fails at BOOT and takes down **every** endpoint with a 500, not just the new route. That happened (`TemplateTestController` → `WhatsappService`, `WhatsappModule` not imported; it is not `@Global`).
- **`web.config` has `loggingEnabled="false"` — there are no iisnode log files.** To see why the API is failing, run the compiled app directly; the Nest error prints in one shot.
- To prove a fix **while the pool is still up**, compile to a scratch dir INSIDE the repo (`--outDir dist-check`, so `node_modules` still resolves), boot-test that, then delete it. `dist` is locked while iisnode runs.

## Conventions
- **Design = "calm & data-clear"** (Apple discipline + functional financial color). Neutral base, hairline borders, indigo on CTAs; **semantic green/red only for financial signals**. Listed chip = light purple; Print Forms CTA = light red `#fdebea`/`#b3372e`. **Never copy competitor UI** (IPOJI/IPOGuru studied for features, not looks).
- Reusable admin UI lives in `apps/web/components/ui` — incl. **SearchSelect** (type-to-filter combobox; list renders via portal because admin `.card` is `overflow:hidden`; also used on the consumer profile form for the UPI handle), **Toast** (top-right toasts), `.filter-row` (aligns filter fields + buttons; `.field` carries an 18px bottom margin).
- **Web and mobile keep the profile form in step by hand** (different frameworks, no shared component): split UPI input (name grows / handle fixed + filterable) and the one-line NSDL-CDSL explainer exist twice — `apps/web/components/Account.tsx` and `apps/mobile/app/profiles/new.tsx`. Change one, change the other. Widths differ on purpose (handle 158px web / 124px mobile — the phone row has less room).
- **One type contract** — shared types, the bid engine, the glossary, `format.ts` (`titleCase()`, `shortName()`, the `LABEL` vocabulary, `demandWord`), `stage.ts` AND the issue engine (`computeIssue.ts` + `issueRules.ts`) live in `packages/shared-types`. Web and mobile IMPORT these; never re-implement locally. Derived figures used by more than one surface belong in ONE helper too — `categoryLanes()` in `HeroBanner.tsx` feeds both IPO-slide treatments, `issueInputsFor()` feeds every issue derivation.
- **Nest sends an EMPTY body for a `null` handler result** — not the string `"null"` — so `res.json()` throws "Unexpected end of JSON input". Every web API client (`consumer-api.ts`, `tenants-admin.ts`) reads the body as text and treats an empty 200 as `null`. This broke `/partner/apply` for every first-time visitor.
- **CSS: check for a name collision before adding a class.** `globals.css` is one big global sheet and it has bitten FOUR times: `.sh` inherited a section utility's 76px padding and blew the banner 302→495px; `.nav-link` was defined for BOTH the front-site header and the admin sidebar, and the admin copy (later in the file) dragged `display:flex; gap:11px; width:100%` onto the site nav — the hole between "IPOs" and its count badge (admin rules now scoped to `.admin-side`); a candidate slide named `.steps` hit the apply-flow stepper's `margin: 10px 0 28px`, and since a stretched flex item's height is the container MINUS its margins, that slide rendered 38px short; `.gl-page` lost to `.trust-page`'s later `max-width`. Grep first, prefix banner/page classes (`hb-`, `hbn-`, `hbs-`, `hbp-`, `brd-`, `sd-`). The build catches none of it; **measure the live DOM**.
- **Prefer explicit values over "looks about right"** when two controls must match: the status track and the board meter are both pinned to a stated 40px (32px button + 3px padding + 1px border), not to padding that drifts the moment a font size changes.
- **Anchor jumps under a sticky bar need JS, not CSS.** `html` carries `scroll-padding-top` AND the target carries `scroll-margin-top`, and the two ADD — which parked glossary/FAQ headings 137px below the bar. `scrollToSection()` in `lib/useScrollSpy.ts` positions from the bar's **stuck** height (its sticky `top` + its own height); its live rect is wrong before it sticks, which is why the first click on a fresh page missed by 167px.
- **Two scroll gotchas that only appear at runtime**: `IntersectionObserver` scroll-spy picks the topmost *intersecting* section, which for tall sections is the one already scrolled PAST — read positions directly instead. And `scrollIntoView({ block: 'nearest' })` scrolls the nearest scrollable ancestor in the VERTICAL axis (the page), so using it to keep a chip visible in a horizontal strip fights any smooth scroll in flight — set `scrollLeft` instead.
- **`requestAnimationFrame` does not fire in a hidden tab.** Throttle scroll handlers on a timestamp; the Browser pane reports `document.hidden` and `prefers-reduced-motion: reduce`, so rAF loops and CSS animations cannot be observed there — verify their wiring, not their motion.
- **Web ≠ mobile by design**: web is the research + SEO surface (density, tables, full detail, trust signals, conversion for anonymous visitors); mobile is the task surface (speed, one CTA per stage). What must stay identical: vocabulary, status wording, Title-Case names, semantic colours, the GMP disclaimer.
- **Status colour is a COLOUR CODE: one colour per status, no two statuses share one.** `STAGE_TONE` in `packages/shared-types/src/stage.ts` is the single map — Live/Open Today **green `#12925a`** · **Closing Today · Closed · Withdrawn red `#d8412a`** · Pre Apply **light indigo `#7565bd`** · Upcoming **indigo `#3c2e7e`** · Awaiting Allotment **teal `#2b8a96`** (was grey; changed 2026-09-02 — grey read as an absence of status rather than a status, and teal is the one family no other status uses) · Allotment Out **gold `#e6ad12`** · Listed **purple `#9b7fd4`**. TWO families share a colour and only two: Open Today *is* Live on day one, and Closing Today / Closed / Withdrawn are one event caught at different moments. Inside a family the card separates states with a `solid` fill, never a second colour. Web reads it through CSS variables (`.t-*` sets `--tone` · `--tone-soft` · `--tone-ink` · `--tone-solid`/`--tone-on` · `--tone-acc`); raw status/phase class names (`.ph.live`, `.ic-dot.open`, `.status.upcoming`…) are **aliases on those same rules**. **Never write a colour next to a status name.** Closing Today is the one status allowed to borrow the loss red — that is a deliberate exception to "semantic green/red only for financial signals".
