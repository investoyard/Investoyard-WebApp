## Status (as of 2026-09-23) — LIVE, deployed on this Windows server
- **Web**: https://newipo.finwave.co — Next.js **static export** (`apps/web/out`) served by IIS. Deploy = `cd apps/web && npm run build` (instant, no pool involved).
- **API**: https://newipoapi.finwave.co/api — NestJS via **iisnode** from `apps/api/dist`. Deploy needs the **app-pool handshake** (see below).
- **DB/Redis**: portable Postgres :5433 + Redis :6379 — **NO Docker**. After any reboot: `scripts\db.ps1 start` + `scripts\redis.ps1 start` (or `scripts\start-services.bat`). A downed DB looks like a CORS/500.
  - **`db.ps1` is service-aware** (2026-09-23): `start|stop|status|register|unregister`. It drives the Windows service `investoyard-postgres` when one exists and falls back to `pg_ctl` when it doesn't, so it behaves the same either side of registration. **`register` must run ELEVATED** (SeCreateServicePrivilege) and checks that BEFORE stopping anything, so a refusal costs nothing. LocalSystem is safe because `pg_ctl` spawns postgres with a RESTRICTED token — Postgres aborts if it holds administrator rights, which is also why this goes through `pg_ctl register` and not `sc create`. Registration passes **`-l log.txt`**: without it a service sends stderr to the Windows event log and `.pgdata\log.txt` stops growing, and that file is where every crash so far was diagnosed.
  - **A crashed Postgres leaves a ZOMBIE**, and `db.ps1 start` now clears it automatically (2026-09-23). Symptom set: `pg_ctl status` says **"no server running"**, yet a `postgres` process is alive, **5433 is still LISTENING**, and `start` warns *"another server might be running"* then fails with *"could not open log file … Permission denied"* — the orphan holds both the socket and the log. `Clear-PgZombie` acts only on that exact three-way combination (no postmaster **and** orphan processes **and** the port held); anything looser would be killing a healthy server, and it removes `postmaster.pid` only once both are provably gone. WAL replay on the next start is the normal, non-destructive recovery; nothing committed is lost.
  - **Check Postgres by CONNECTING, never by probing :5433.** An orphaned backend keeps the listening socket, so an open port is exactly what a crashed server looks like — `start-services.bat` used to test the port and reported **UP** for a database refusing every query, while also telling the operator that the zombie's warnings meant *"Postgres was ALREADY running - that is fine"*. Both are gone. The check is now `pg_isready -h 127.0.0.1 -p 5433` (expect *accepting connections*) and `redis-cli -p 6379 ping` (expect *PONG*), and the API is the final word: `curl -H 'Host: newipoapi.finwave.co' http://127.0.0.1/api/health` must be **200**, not 503.
  - **Never `npm run build` the web while the API is down** — the static export is generated from the LOCAL live API (`API_INTERNAL_URL=http://localhost:3000/api`, via the Host-header forwarder). Against a dead API it bakes an empty catalog AND collapses every dynamic route to the `no-ipos` placeholder, wiping ~1,000 real IPO pages. The build log naming 1,000 `/ipos/[symbol]` paths is the proof it had real data.
  - **A build that ran while the DB was dying POISONS `.next/cache`, and plain rebuilds replay it.** `safeGet()` uses a cacheable `fetch` (required by `output: export`), so a failed response is cached like any other and **two clean rebuilds against a healthy API reproduced the damage exactly** (2026-09-23). The cure is `Remove-Item -Recurse -Force apps\web\.next\cache` before rebuilding — the comment on `safeGet` says so, and it is easy to read past.
  - **The failure is PARTIAL and silent, which is what makes it dangerous.** The build does not fail: `safeGet` swallows the error and returns its fallback, so the log still prints ~1,000 routes and looks perfect while individual pages lose whole sections. On 2026-09-23 four IPOs that were OPEN shipped detail pages with no Live Subscription section at all. **Route count is not proof of a good build** — spot-check a page's content: `grep -c timesSubscribed apps/web/out/ipos/<slug>/index.html` should be non-zero for anything currently subscribed.
- **Mobile**: Expo **SDK 54** (Play-Store Expo Go works). Dev: `cd apps\mobile; $env:REACT_NATIVE_PACKAGER_HOSTNAME='103.107.27.38'; $env:EXPO_OFFLINE='1'; npx expo start --clear`.

### API deploy handshake (CRITICAL)
iisnode locks `dist` + the Prisma engine DLL while the pool runs. **User** stops the pool → then:
`npx prisma generate` (only if schema changed) → `npx tsc -p tsconfig.json --outDir dist` → **user** starts the pool.
- `npx prisma db push --skip-generate` is SAFE while the pool runs; `prisma generate` is NOT.
- New-Prisma-model code shows "property does not exist on PrismaService" typecheck errors until the handshake — expected, not a bug.
- **NEVER run root `npm run build` (turbo) while the pool runs** — nest's clean step guts `dist` and causes a delayed outage. Build workspaces individually.
- Seed is CLEAN-SLATE — never run against prod. Use `npm run ensure-roles` for additive role changes.
- **ALWAYS boot-test before handing the build back**: `PORT=3999 node dist/main.js` and look for "Nest application successfully started". `tsc` passing proves NOTHING about dependency injection — a controller injecting a service whose module wasn't imported fails at BOOT and takes down **every** endpoint with a 500, not just the new route. That happened (`TemplateTestController` → `WhatsappService`, `WhatsappModule` not imported; it is not `@Global`).
- **`web.config` has `loggingEnabled="false"` — there are no iisnode log files.** To see why the API is failing, run the compiled app directly; the Nest error prints in one shot.
- To prove a fix **while the pool is still up**, compile to a scratch dir INSIDE the repo (`--outDir dist-check`, so `node_modules` still resolves), boot-test that, then delete it. `dist` is locked while iisnode runs.

## Conventions
- **Design = "calm & data-clear"** (Apple discipline + functional financial color). Neutral base, hairline borders, indigo on CTAs; **semantic green/red only for financial signals**. Listed chip = light purple; Print Forms CTA = light red `#fdebea`/`#b3372e`. **Never copy competitor UI** (IPOJI/IPOGuru studied for features, not looks).
- Reusable admin UI lives in `apps/web/components/ui` — incl. **SearchSelect** (type-to-filter combobox; list renders via portal because admin `.card` is `overflow:hidden`; also used on the consumer profile form for the UPI handle), **Toast** (top-right toasts), **Tooltip** (below), `.filter-row` (aligns filter fields + buttons; `.field` carries an 18px bottom margin).
- **`Tooltip`** (`components/ui/Tooltip.tsx`, 2026-09-23) — hover / focus / tap popover, **portalled to `body`** because `.ipocard` is `overflow:hidden` (its rounded corners clip the radial wash and the left rail), same reason SearchSelect portals out of the admin `.card`. Three things it got wrong first and now encodes:
  - **`render` is a FUNCTION, not a node.** A list page mounts sixteen of these; the contents (a subscription table each) must only be built while one is open.
  - **A scroll REPOSITIONS it; it does not close it.** Closing looks like the cheap option and is wrong — `HTMLElement.focus()` scrolls its target into view, so tabbing to an off-screen trigger opened the tooltip and the scroll that very focus caused dismissed it in the same tick. It closes only when the trigger leaves the viewport. Scroll/resize are coalesced to one measure per `requestAnimationFrame`.
  - **`z-index: 190`** — above the sticky header (50) and every dropdown (60–80), UNDER the modal overlay (200). A tooltip must never float over a dialog it cannot belong to.
  - Testing note: `el.focus()` is a **no-op when the window itself isn't focused**, which the Browser pane often isn't — a tooltip that "doesn't open" there may open fine for a user. Drive it with `.click()` instead.
- **Web and mobile keep the profile form in step by hand** (different frameworks, no shared component): split UPI input (name grows / handle fixed + filterable) and the one-line NSDL-CDSL explainer exist twice — `apps/web/components/Account.tsx` and `apps/mobile/app/profiles/new.tsx`. ## Subscription poller — cadence + tuning
- **Live-tunable via `admin → Integrations → 'Live subscription poller — cadence & window'`**. Provider key `subscription` with fields: `normalSec` (default 60), `fastSec` (default 5), `fastWindowMin` (default 90), `fromMin` (default 600 = 10:00), `toMin` (default 1080 = 18:00). Poller reads `providers.effective('subscription')` on each tick with the 60s config cache TTL, so overrides take effect within a minute — **no pool restart** needed for cadence tweaks. Bad values (non-numeric, ≤0) fall back to defaults per-field so a typo can't stall the loop.
- **Window: 10:00–18:00 IST**. `OPEN_TO_MIN` is `18 * 60` — 1-hour grace past the 17:00 SEBI bidding cutoff so NSE catwise and BSE demand-schedule can serve consolidated / finalized numbers for another 30-60 min on closing day. Was 17:00 sharp until 2026-09-21 when NSE's final subscription never got written.
- **Fast mode**: last 90 min before 17:00 (i.e., from 15:30 IST) AND through the 17:00-18:00 grace hour uses `FAST_MS` (5s default) instead of `NORMAL_MS` (60s default). `BIDDING_CLOSE_MIN = 17 * 60` is the fixed regulatory anchor for the fast-window trigger; `OPEN_TO_MIN` (poller cutoff) is separate and tunable.
- **BSE per-category bids are FUDGED** (per operator's original C# workflow) — BSE ships `totalapplication` as a scalar for the whole issue. Back-solve for hni / hni2 / shareholder / **employee** from NSE avg shares-per-bid; retail absorbs the remainder. Employee was excluded from this loop until 2026-09-21 (NSE closing day) — Employee BSE bids were silently folded into Retail's residual, understating Employee applications by 12k+ and inflating Retail by the same.
- **60s config cache TTL** is the whole reason live tuning works without a restart. The `subscription` provider config's settings JSON drives cadence directly.
- **Manual refresh returning `0 of 3 open updated` is NORMAL**: `refreshIpo` returns `true` only when numbers CHANGE, `false` when they're identical to the last snapshot (writes-on-change gate). "Updated" ≠ "polled" — all 3 IPOs are still being queried.

## ASBA print — flatten guarantee for WhatsApp forwarding
- **`fillAsbaAcroForm()` in `apps/api/.../asba-acroform.ts`** guarantees a **fully-flat PDF** on the `flatten=true` path. When per-field appearance streams don't all build (ARDEE-style blanks missing `/DR`/`/DA`), fast `form.flatten()` bails — the code then **burn-ins** each field's value at its widget `/Rect` using the embedded Helvetica AND removes every widget annotation from every page's `/Annots` array (both live widgets AND dangling `PDFRef`s from the earlier bad-widget cleanup). Then deletes the AcroForm shell.
- **Why widgets matter**: `pdf-lib`'s `form.removeField()` only unlinks a widget's annotation from a page when the widget's `/P` (page ref) is set. Many SEBI templates skip `/P`, so removeField leaves orphan widgets. Viewers still render highlighted empty form-field boxes over the burned-in text — the PDF LOOKS half-filled. The belt-and-braces sweep of every page's `/Annots` catches both live widget dicts AND dangling refs. ELEVATE_TEST.pdf: 38 orphan widgets → 12 (dangling) → **0** ✓.
- **Why this exists**: WhatsApp's in-app viewer (Android + iOS) **ignores `/NeedAppearances`**. Adobe Reader / Chrome / iOS Files honour it and regenerate appearances at open time; WhatsApp doesn't. Every partner-API PDF is forwarded through WhatsApp by the operator's brokers, so `/NeedAppearances` fallback = customer receives a blank form. Guaranteed flat = works everywhere.

Only **B04** stays in the form, as a post-condition that should be unfalsifiable.
- **B02 enforces the NII split as a RATIO, not as `10` and `5`.** `RulePack.niiSplit` used to be `{big:10, small:5}` and was never read by anything; it is now `{big:2, small:1}` and drives the check. Absolute per-row bounds would be wrong: ICDR sets a *floor* on NII under 6(1) and a *ceiling* under 6(2), not an exact figure, so a 6(1) issuer may legally offer 24/12 — which a hard `max: 10` would reject. `bounds` is now `Record<string, CategoryBound>` keyed by category, plus the pseudo-key **`nii`** for the combined quota (a 20% NII split correctly 2:1 looks fine row by row and is caught only in aggregate). **Big < Small blocks** (the transposition, a data-entry defect that published wrong figures on three records); an off-ratio split that is not transposed is **W01, a warning** — an unusual split is the issuer's business. B01 *has* to: Step 3 absorbs the floor-to-lot residual into one category, so a table summing to 99.9% still satisfies `Σ shares == net_offer_shares` and every post-condition passes — the shortfall is silently handed to the residual holder. Checked only in the admin form (as it was), the Excel importer and the API derive a clean-looking wrong answer. **B09/B10 don't stack**: a fixed-price pack caps the anchor at 0, so reporting both would tell the operator to *reduce* a percentage they need to *remove*.
- **Anchor % of QIB is now an input** (`extra.anchorPct`, Offer & Reservation tab) with anchor shares / net QIB derived beside it. Before this the rule pack's `anchorMaxPctOfQib: 60` existed with nothing to compare against — B09 was unreachable from every surface.

## Messaging: delivery log + test sends
